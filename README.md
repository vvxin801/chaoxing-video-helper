# 视频播放助手 · 自动连播（Edge / Chromium 扩展）

一个只做一件事的浏览器扩展：**你看视频的时候，一集结束自动接下一集；一个小节里所有视频都播完，才切到下一小节**，省掉每次去点“下一集 / 下一节”的动作。

它会先认出“你现在看的是这一节的第几个视频”，**从当前这个往后接**：你从第 3 个开始看，就接第 4、5 个，不会把你没看的第 1、2 个翻回去补播；等这一节走到头，切到下一小节时会**从下一小节的第 1 个视频重新开始**。

针对学习通（`chaoxing.com`）等把视频放在 iframe 里、把“下一集”按钮放在外层页面的课程页做了适配，但判断逻辑不是写死某个站点，而是“候选按钮打分 + 点击后验证”，所以其他课程平台、播放列表页一般也能用。

从 1.3.0 起，它还多了一个**自动答题**：在章节测验 / 作业页里把题目抓出来，交给 AI（或你自己的题库接口、本地题库）取答案，自动填进选项和输入框；到提交这一步会先停住，默认不替你交卷。1.3.1 又补上了**视频弹题**：视频播到一半弹出来的小测（判断题/选择题，选项常常没有 `input`），也能识别、点中答案并提交，让视频继续往下播。1.3.2 修掉了弹题答错后反复重试的死循环；1.3.3 开始按文本结构解析新版章节测验（没有 `input` 的 A/B/C/D 方形选项），并且打开总开关后默认自动运行；1.3.4 能顺手点掉平台弹出的“确认提交?”框；1.3.5 起选项字母被伪元素藏起来时按排列顺序兜底；1.3.7 让弹题里藏着的 `radio` 真正被选中、不再“看着点了其实没选上”；1.3.9 默认自动交卷、交完自动点“下一节”；1.3.10 补上了题目在 iframe 里、以及“题干和选项是平级 div”的页面；1.3.11 起题目在跨域 iframe 里、外层页面读不到 DOM 也能答；1.3.12 把“确认提交?”的确认也扩展到了外层包装页面：题在 iframe 里、确认框却由外层弹出时，扩展也会自动点掉；1.3.13 把“提交”这一步做稳了——一次只点一下，点不动会换候选，点完没反应会在日志里说清楚；1.3.14 让视频弹题答错后自己换一个选项再交，直到答对；1.3.15 让“确认提交?”的自动点击更耐造——观察器 + 定时兜底，外层包装页 60 秒内都认；1.3.16 起，答题模块切到下一节后，新页面的视频会自动开始播放，不用再手点播放按钮；1.3.17 把“交卷”这一步补稳——确认框出现得慢也会等，点不掉会重试，点掉后一定接着切下一节；1.3.18 认出学习通自己的 `#workpop > .popDiv` 确认弹层（之前只认 layui/element，所以日志说收到了交卷消息却一直没点）；1.3.19 让切完小节后的自动播放也能在跨域 iframe 的播放器里生效；1.3.20 等播放器真正加载出来再按播放，并把“续播停在结尾、看着像没播”的视频从头放；1.3.21 让催播连 shadow DOM 里的 `<video>` 也能找到；1.3.22 把“视频在子页面里”说清楚，并把每次催播的结果提示出来；1.3.23 修掉“切节后因为已完成记录/启动状态而跳过播放”的问题，并把失败原因分清楚。

## 它做什么 / 不做什么

**做：**

- 视频播放到结尾时，在页面顶部弹出倒计时条，倒计时结束自动点击“下一集/下一节/继续播放”
- 一个小节里有多个视频（学习通的常见结构）时，**先把这一节里的每个视频依次播完，全部播完才跳到下一节**——不会刚播完第一个就跳走
- **从你在看的那个视频往后接**：视频和子 frame 按页面里的位置排成一列，播完一个只往后找下一个，绝不回头；切到新小节后，会自己把新小节的第 1 个视频放起来
- 点击后**会验证是否真的切换了**（URL 变化、视频元素换了、进度归零或页面重载），没切换成功就换下一个候选再试
- 倍速记忆（按站点）、进度续播（按页面）、悬浮面板、快捷键
- 播放器不派发 `ended` 事件时，用**画面识别兜底**：视频接近结尾时连续多帧静止 / 全黑 / 进度停滞，也判定为播放结束
- **自动答题**（1.3.0 新增）：认出单选题 / 多选题 / 判断题 / 填空题 / 简答题，抓题干和选项；答案可以来自 AI（OpenAI 兼容接口）、你自己的题库接口，或者导入的本地题库；自动填选项、填多个空、写简答
- 答题有独立的悬浮面板：“开始答题”按钮 + 每道题填没填上的日志；页面 DOM 变化会自动重扫
- **视频弹题**（1.3.1 新增）：课程视频里弹出来的判断题/单选题/多选题，选项是普通 `li`、没有 `input` 也能识别；按答案点中选项，再点弹题的“提交/确定”，让视频继续；开了“自动答题”的自动运行后，弹题出现会自己答
- **安全边界**：考试页只填不交卷；章节测验的“自动交卷”默认开启（可从设置关掉），考试页无论如何都不会点提交或确认

**不做（这是设计上的边界）：**

- 不修改、不伪造任何平台的学习记录或进度上报
- 不模拟“人在看”的鼠标移动/焦点事件来骗过检测
- 不做“关掉浏览器也自动刷完”的后台挂机
- 除了**你自己配置的答题接口**（AI / 题库），不向任何第三方发数据；没有配置时扩展完全不联网

它只是个“播放器增强”：你真的在播放视频，它替你点一下下一集。

## 安装

1. 打开 Edge，地址栏输入 `edge://extensions/`
2. 左下角（或右上角）打开 **开发人员模式**
3. 点 **加载解压缩的扩展**，选择本目录 `video-auto-next`
4. 固定到工具栏（可选）

装好后打开任意视频页，右下角会出现悬浮面板；点面板展开，或点工具栏图标打开设置。

> 权限说明：只需要 `storage`（存设置、进度、题库和答案缓存）。`host_permissions` 声明为所有站点，是因为课程视频可能在任何域名下；另外答题时要在后台脚本里请求你配置的 AI / 题库地址，内容脚本直接请求会被 CORS 拦掉，所以这次加了 `background.service_worker`。**只有你点“开始答题”、且配置了接口时才会发请求**，视频连播部分仍然不联网。

## 使用

打开课程视频页 → 正常播放 → 一集播完 → 顶部出现“N 秒后播放下一集” → 自动切到下一集。

- 同一小节里有多个视频时，播完一个会先接着播这一节里的下一个（右下角会提示“这一节还有 N 个视频”），等这一节全部播完才出现倒计时、才去点“下一节”
- 倒计时期间按 `Esc` 或点“取消自动切换”，就停在当前页面
- 悬浮面板（右下角）可以直接切换倍速、开关自动连播
- 工具栏图标打开的设置面板里可以改：倒计时秒数、倍速记忆、进度续播、画面识别、悬浮面板、键盘快捷键、自定义选择器

### 快捷键

| 键 | 作用 |
| --- | --- |
| `N` | 立即切到下一集 |
| `[` / `]` | 减速 / 加速（0.5× ~ 3×） |
| `\` | 倍速复位 1× |
| `J` / `L` | 快退 / 快进 10 秒 |
| `K` | 播放 / 暂停 |
| `M` | 静音 |
| `F` | 全屏 |

快捷键在输入框里不会触发；不需要时可在设置里关掉。

### 自动答题

**先说边界**：这部分只适合章节测验、作业、课后练习这类“允许查资料”的场景。**考试页（URL 里有 `/exam`、`exam-ans`，或标题带“考试”）只填答案、绝不会自动交卷**；章节测验的自动交卷默认也是关的，需要你自己在设置里打开。用它之前请确认课程/学校的规定，后果自负。

1. 点工具栏图标打开设置，展开 **自动答题**，打开“在测验/作业页启用”（默认关闭）。
2. 选答案来源：
   - **AI**：填接口地址（默认 `https://api.deepseek.com`，兼容任何 OpenAI 格式的 `/chat/completions`）、API Key、模型名（默认 `deepseek-chat`）。一次最多送 6 题，返回 JSON 答案。
   - **题库接口**：填 URL / 方法 / Headers / Body 模板，模板里可以用 `{{q}}`（题干）、`{{o}}`（选项）、`{{t}}`（题型）、`{{token}}`；返回 JSON 里会自动找 `answer` / `answers` / `correct` / `key` 之类的字段，也可以填 `answerPath`（如 `data.answer`）精确指定。
   - **本地题库**：支持 `.json` / `.csv` / `.tsv` / `.txt`，一行“题目----答案”，或 `题目<Tab>答案`；匹配是先精确、再按相似度（阈值 0.9）。题库存在 `chrome.storage.local`，不上传。
3. 打开测验页，右下角会出现 **答题面板**（只有开了开关或 URL 带 `?vanqa=1` 才出现，避免看视频时碍事）：点 **开始答题**，面板会显示每道题填没填上、失败原因。
4. 默认填完自动提交、自动确认“确认提交?”弹层，交完还会自动点“下一节”；不想自动交可以在设置里关掉“填完自动提交”（考试页仍然不会交）。

答案会按“题干哈希”缓存在本地（最多 2000 条），同一道题第二次直接命中，不再烧 API 额度；设置里有“清空答案缓存”。

![答题面板](test/artifacts/qa-panel.png)

**视频弹题**（1.3.1）：

5. 课程视频播到一半，画面里弹出判断题/单选题时，面板会从“课程页面”变成“视频弹题”，题目数、已填数跟着变；开了“自动运行”的话，弹题一出现就会自己答，不用点“开始答题”。
6. 答完会自动点弹题自己的“提交 / 确定”按钮——弹题不提交视频就卡在那儿，所以这一步不设确认；它点的是弹题的小按钮，**不是整页的“交卷”**，考试页的“不自动交卷”规则不受影响。
7. 弹题选项常常是普通 `<li>`（没有 `input`），扩展会按“选中样式”（`active` / `selected` / `ans-videoquiz-opt-active` 等）判断有没有点上；如果点完没反应，面板日志会写“弹题填好了，提交…”，可以对照页面看选中样式是不是别的类名。

> 你截图里那种“视频画面中间弹出判断题、左下角面板显示 0 题”的情况，就是 1.3.0 只认章节测验 DOM 导致的；1.3.1 已经能认出 `.ans-videoquiz-box` 这一套结构。

> 调试参数（只在 `?vanqa=1` 的页面上生效，不写存储）：`vanqaAi=<接口地址>` 临时指定 AI 接口、`vanqaProvider=ai|api|bank` 临时换来源、`vanqaSubmit=1` 临时打开自动交卷。`test/e2e-quiz.mjs` 就是靠这几个参数在没有真实 Key 的情况下跑通全流程的。

**1.3.2 的变化**：

- **弹题答错不再死循环**：点完弹题提交后会等 1.8 秒看结果——弹题消失就算通过；出现“回答错误 / 答错 / 正确答案”之类的提示，或者弹题一直不消失（同一题自动提交到第 2 次），就停手并在日志里写“这道弹题之前答错过，已停止自动重试”。换到下一道弹题（题干变了）会重新计数。
- **面板多了“复制结构”**：新版章节测验页面（不是 `.questionLi` 那套 DOM）现在会显示“课程页面 · 0 题”。点面板右下角的“复制结构”，会把页面里最像题目的几个节点的 `class` / `id` / 一段 HTML 复制到剪贴板；把它发出来，就能按真实结构补选择器。
- **新版章节测验还没有适配**：目前认的是老版 `.questionLi` / `.Zy_TItle` / `input` 那套。你截图里“1【多选题】…、选项是 A/B/C/D 方形行、没有 input”的页面属于新版结构，这一版还抓不到，需要先拿到它的 DOM。

**1.3.3 的变化**：

- **新版章节测验按文本结构解析**：不再要求有 `input`。扩展会找“带 `【多选题】` 之类标记”的题干，再找题干附近“A 红色传递… / B 绿色…”这样一行行的选项，点选后靠 `active` / `selected` / `is-checked` 之类的类名判断选中。你截图那种“`2【多选题】…` + A/B/C/D 方形行”的页面现在能认出题目了（识别成功时日志会写“按文本结构认出 N 题（新版页面）”）。
- **打开总开关后默认自动跑**：以前“在测验/作业页启用”和“自动运行”是两个开关，很多人只开了第一个，于是每次都要手点“开始答题”。1.3.3 起 `qaAutoRun` 默认打开，升级时也会把“开了总开关但没开自动运行”的配置迁移成自动跑（只迁移一次，之后你在设置里手动关掉就听你的）。页面异步加载出题目时，也会在扫到题后补一次自动开始。
- **提交按钮认 div/span 了**：新版页面的“提交”不再是 `<button>`，之前会报“没找到提交按钮”。现在 `div.btn` / `span[class*=submit]` 这类也会被认出来（仍然跳过带 `confirm()` 的）。

> 新版结构毕竟是按文本猜的：如果页面把题干和选项拆得很碎、或者选项字母不是 A-H（比如 ①②③），还是会漏。这时点“复制结构”把 DOM 发出来，按真实类名补规则最稳。

**1.3.4 的变化**：

- **自动交卷会点“确认提交”了**：学习通点完“提交”常常再弹一个自己画的确认框（“确认提交?” + 取消/提交）。以前扩展点完主按钮就停住，等你去点确认，自动交卷等于没交成。1.3.4 点完主按钮会等最多 2.5 秒，认出这类确认框（layui / element / antd / 原生 div 弹层）并点掉里面的“提交 / 确定 / 确认”，日志会写“点了确认框里的「提交」”。只在**开启了自动交卷**、并且是作业/章节测验页时才会走到这一步，考试页依旧只填不交。
- **点不到确认按钮会说明原因**：确认框出现了但里面没有“提交/确定”这类按钮（比如要输验证码、要拖滑块），日志会写“弹出了确认框，但没找到确认按钮，请手动点一下”，不会乱点“取消”。

> 浏览器**原生**的 `confirm()`（标题栏灰色、没有叉号的那种）内容脚本改不了，遇到带内联 `confirm()` 的提交按钮仍然会跳过并提示手动提交。

**1.3.5 的变化**：

- **选项字母画在圆圈里的题也能答了**：有些单选题的 A/B/C/D 不在文本里，而是用 CSS 伪元素/背景图画在圆圈中，DOM 里每行只剩“实验室最常用的一种纯水”。以前这种题会被判成“没认出选项”，于是单选/多选题留空、连带自动提交也不触发。现在认不出字母前缀时，会按“同一排、宽度相近、2~8 个块”把它们当成 A、B、C… 顺序点选，日志会写“其中 N 题选项没有 A/B 前缀，按排列顺序认”。
- 这个兜底只在正常解析失败后才用，而且要求这一排里没有别的题干、块宽度比较整齐，不会把导航或按钮当成选项。

> 如果还是有一道题留空导致不自动交卷，面板日志会写“还有 N 题没填，先不自动提交”，把日志和“复制结构”的内容发出来即可定位是哪一步没认出来。

**1.3.6 的变化**：

- **填完 Key 不用刷新页面了**：以前答题请求会带着“页面打开那一刻读到的配置”，如果先开学习通、后去设置里填 Key，页面上还是旧配置，日志会一直报“还没填 API Key”。现在后台每次取答案都以 `chrome.storage.local` 里的最新 `qaConfig` 为准，页面里也监听配置变化；填好保存后直接重新点“开始答题”就行。调试参数（`?vanqaAi=` 等）仍然会临时覆盖，不会被存储里的配置盖掉。
- 缺 Key 的报错也写清楚了入口：浏览器工具栏 → 扩展图标 → 答题设置 → AI，填好保存后重新点“开始答题”。

**1.3.7 的变化**：

- **视频弹题“看着选了、其实没选上”**：弹题的选项行里可能藏着原生 `radio`，以前只点外层 `li`，页面不认；现在会先点，没选中就再点里面的 `label`/圆圈，最后直接把 `radio.checked` 置上并补发 `input`、`change`，再确认选中。
- **“已填 0”不再虚报**：以前点一下就记一次“已填”，即使页面没真的选中；现在必须读到选中状态（`checked`/`aria-checked`/`active` 类）才算填上，没填上会明确报“没填上”，并且同一道弹题最多自动试 2 次，不会无限循环。
- **“复制结构”现在包含弹题的真实 HTML**：视频弹题和章节测验的类名完全不同，出问题时点一下“复制结构”，会把弹题外层的 HTML 一起复制进去，方便按真实结构适配。

> 如果弹题还是选了 A 而正确答案是 B，点“复制结构”把内容发我，里面现在有弹题的完整标签结构。

**1.3.8 的变化**：

- **确认框现在谁点出来的都会自动确认**：以前只有"扩展自己点提交"之后才会去找“确认提交?”弹层；你自己点提交时它不会管。现在页面里常驻一个确认框监听，只要开了“自动提交”、且不是考试页，弹层出现就会点掉，并写日志“检测到确认框，自动点了「提交」”。没开自动提交时会提示一次，不会静默。
- **章节测验异步渲染的识别**：`/mycourse/studentstudy` 这类 URL 看不出是不是测验，题目又是后加载的；现在会按页面里的“【单选题】/【多选题】/【判断题】”文字触发识别，并在 1.5 秒后补扫一次，避免面板一直停在“0 题”。
- 考试页仍然只填不交、也不会去点确认框。

**1.3.9 的变化**：

- **默认就自动交卷了**：“填完自动提交”改成默认开启；已经在用扩展、当初没开过的，升级后会自动打开一次（只迁移一次，之后你手动关掉就听你的）。
- **交完自动下一节**：新增“交完自动下一节”开关（默认开）。提交并确认成功、确认框关掉之后约 2.6 秒，会点页面底部的“下一节 / 下一章 / 下一讲”，接着做下一小节；考试页不会切。找不到按钮会在面板日志里说明。
- 确认框监听、自动交卷、自动下一节都只在**非考试页**生效。

**1.3.10 的变化**：

- **题干和选项是“平级 div”的页面也能认了**：有些章节测验里，题干和 A/B/C/D 几行是同一层的兄弟节点（没有共同的题目容器），以前按“包含关系”找题块会漏掉。现在会退一步读页面的文字流：按 `【单选题】` 切题、按行首 `A/B/C/D` 切选项，再按选项文字反查页面上能点的元素，点完同样要看到选中状态才算填上。
- **题目在 iframe 里也能扫到**：`/mycourse/studentstudy` 有些小节把测验塞进同源 iframe，外层页面抓不到题、面板一直“0 题”。现在主文档没认出题目时，会翻同源 iframe 的文档再解析一遍；提交按钮、确认框、“下一节”也一起在 iframe 里找。
- **出错不再静默**：答题过程中真抛异常时，面板日志会写“答题出错：…”，不会停在“取答案中”。

**1.3.11 的变化**：

- **题目在跨域 iframe 里也能答了**：有些章节页把测验放在 `about:blank` / `srcdoc` / 别的子域名的 iframe 里，外层页面既读不到它的 DOM（面板显示“7 个 iframe，0 个同源可读”），也认不出 URL 是学习通。现在扩展会给这类 iframe 也注入脚本（`match_origin_as_fallback`），子页面只要检测到题目文字就自己接管、自己填答和提交。
- **“复制结构”能带上子页面的结构**：外层读不到跨域 iframe 的内容，所以点“复制结构”时会向所有子页面发一次请求，把它们的 URL 和题目 HTML 一起收集进来再复制；日志会写复制到了几个子页面。
- 跨域子页面里的确认框、提交按钮也由子页面自己的脚本处理，外层不会再“等一个永远到不了的 0 题”。

**1.3.12 的变化**：

- **确认框在外层弹出，也能点掉了**：有些章节页的题型在 iframe 里，点“提交”之后平台把“确认提交?”弹在**外层包装页**上。以前只有“有题目文字的那一层”才注册确认框监听，包装层没有题目、URL 也不是学习通，就没人管这个框。现在每个注入脚本的 frame 都会接住子页面发来的“我要交卷了”，只要开了自动提交、且不是考试页，就把这一层的确认框点掉。
- **“下一节”也能跨层点**：子页面答完找不到“下一节”时，会把这件事转给外层页面，由外层点它自己的“下一节/下一章”；只点一次，不会连跳两节。
- 这一层没有题目时不会建答题面板，也不影响原来的视频连播；考试页仍然不点确认、不交卷。

**1.3.13 的变化**：

- **“提交”点了没反应时，会换一个候选再试**：平台上的“提交”有时是包了一层的 `div`，真正绑事件的是里面那个；以前只认第一个，点在外壳上就毫无反应。现在会把所有像“提交”的元素按“按钮 > 链接 > 其它”排一遍，点完看页面有没有反应（弹确认框、按钮消失/变灰、出现“提交成功”、地址变化）；没反应就换下一个，最多试三个，日志会写清楚点的是哪个。
- **点击补上了 pointer 事件**：有些平台的按钮只听 `pointerdown/mousedown`，只调 `click()` 不触发；现在会按顺序补 `pointerdown → mousedown → pointerup → mouseup → click`。
- **修掉“一次提交点两下”**：以前合成点击时既 `dispatchEvent(new MouseEvent('click'))` 又调 `element.click()`，页面会收到两个 click —— 作业可能被重复提交、弹题被重复答。现在只走一次。
- **15 秒内不会重复提交**，并且只有“确认框点掉了”或“页面真的跳走了”才会去点“下一节”，避免提交失败还误跳一节。
- 常驻的确认框监听和提交路径不会同时去点同一个确认框（谁先处理谁占位）。

**1.3.14 的变化**：

- **视频弹题答错会自动换选项再交，直到答对**：以前检测到“回答错误”就停手，等你手动点；现在会记住这次交的答案是哪个，换一个没试过的再提交。判断题就是“对 → 错”这样翻，单选题按 A/B/C/D 顺序换，多选题会把 2~4 个选项的组合都试一遍（最多试 8 次）。
- **答对即停**：弹题消失（答对）就清掉这道题的试错记录，不会影响同一道题以后再次出现；试满次数或换答案点不上时才停手，并在面板日志里说明。
- **重试期间不会重复提交**：换答案的过程中会占住“提交中”，页面的观察器不会拿旧答案再交一次；整个过程仍受 2.5 秒提交间隔限制。

**1.3.15 的变化**：

- **确认框监听改成“观察器 + 定时兜底”**：以前只靠 MutationObserver，页面把 `body` 整个换掉（SPA 切页）、或者确认框恰好在你点提交后的冷却时间里出现时，观察器可能永远看不到它。现在每 1.5 秒还会主动查一次，框在就点掉。
- **子页面交卷消息多留一会儿**：外层收到“我要交卷了”之后，60 秒内弹的确认框都算这次交卷的；以前只认 15 秒，平台慢一点就错过了。
- **会说明为什么没点**：如果确认框出现、但这一层既没有题目文字、也没收到交卷消息，日志会写“页面弹了确认框，但这一层没有题目、也没收到交卷消息，先不动”，方便区分“没识别到”和“故意不动”。
- **“确认提交/确认交卷”这类框放宽了判断**：确认框可能由同级的另一个 iframe 弹出，既不在这层、也不在祖先里。现在只要框里写着“确认提交/确认交卷”，且当前是学习通页面（或这层有题、刚有子页面交卷），开了自动提交就会点。
- **顶层把交卷消息转给所有子页面**：题目在一个 iframe、确认框在另一个 iframe 时，兄弟页面也能收到“有人交卷了”，自己那层弹框就会自动点。

**1.3.16 的变化**：

- **切到下一节后，新页面的视频会自己按播放**：答题模块点完“下一节”会留一个时间戳，视频那一层的脚本看到后，等新小节的播放器加载出来就自动开播（浏览器拦截自动播放时退化为静音播放，点一下视频可恢复声音），不用再手点画面中间那个播放按钮。
- 只认“刚由扩展切换过小节”的 2 分钟窗口；你自己翻到某一节、或手动暂停的视频，不会被它抢着播。
- 切换后如果落到的不是视频任务点（比如又是测验），时间戳会自然过期，不会影响后面的页面。

**1.3.17 的变化**：

- **“刚点过提交”改成全页面共享的时间戳**：点提交时往 `chrome.storage.local` 写一条 `vanConfirmAt`。确认框不管弹在题目所在的 iframe、外层包装页、还是兄弟 iframe 里，那一层的轮询都能凭这个时间戳认领并点掉，不再只靠 `postMessage` 有没有送到。
- **同一个提交按钮只点一次**：以前点完 0.9 秒没看到反应就换下一个候选，慢一点的平台会被点两三次、甚至重复交卷。现在点一次后最多等 3.6 秒，等确认框或成功提示出现；真的没反应才换候选。
- **确认框会重点几遍**：确认按钮有的绑在 `pointerdown`、有的点了还要异步校验。点完 1.2 秒框还在，就再点一次（最多 2 次），这才算真交上去。
- **确认按钮找得更全**：除了 `a/button`，也认 `div/span` 里带 `btn/primary/submit` 的按钮，以及文字在子元素里的嵌套按钮。
- **交完自动下一节**：不管确认框是谁点的，点掉之后都会自己去找“下一节”；如果按钮在别的 iframe 里，会广播让每个子页面各自找一遍。

**1.3.18 的变化**：

- **认出学习通自己的“确认提交？”弹层**：它的外壳是 `#workpop.maskDiv > .popDiv`，既没有 `layui-layer` 也没有 `dialog/modal` 类名，1.3.17 之前的确认框选择器完全匹配不到，所以日志只说“收到子页面交卷消息”，却始终没有“自动点了提交”。1.3.18 把 `.popDiv`、`.maskDiv .popDiv`、`#workpop` 都加进了识别范围。
- **确认按钮也认 `a#popok` 这种写法**：弹层里的“提交”是 `<a id="popok">`，按钮查找、pointer 事件、点击后 1.2 秒复查都按同一套走。
- **“复制结构”更完整**：现在会额外抓一份没点掉的确认框（含识别到的确认按钮），并到同源 iframe 里找题型节点，标注每个候选来自哪个 iframe；题目确实不在 DOM 里时也能从报告里看出来。

**1.3.23 的变化**：

- **切节催播不再被“已看完”挡住**：以前切到新小节后走的是“继续下一个没播完的视频”，如果这一节之前已经看完（进度 ≥98.5%），它会被当成“已完成”直接跳过，看着就是“有视频但不播”。现在切节后的催播是“把这一节正在显示的视频放起来”，不看完成记录。
- **修掉“启动中”状态卡死**：某次播放没成功时，内部状态还留着“正在启动”，下一轮会误以为已经在播、不再重试。现在失败就清掉，继续重试。
- **点画面正中 + 全页找播放按钮**：有些播放器只认点击，而且按钮不在 `<video>` 的父节点里。现在先点视频正中间那层（用户真正点到的地方），再到整个文档（含 open shadow root）找 `vjs-big-play-button`、`xgplayer-start`、`[class*=play-btn]`、`[aria-label*=播放]` 之类。
- **提示能区分原因**：“浏览器不允许子页面自动播放，得在视频上点一下”＝权限策略拦了；“视频还没加载好，会继续重试”＝数据源没到；“有视频但没能自动播放”＝其他原因。`复制结构` 的 `KICK:` 行会带上错误名。

**1.3.22 的变化**：

- **“本页暂无视频”不再让人误会**：弹窗里的“本页”只统计主文档自己的 `<video>`；学习通的播放器在跨域 iframe 里时主文档确实看不见它。现在子页面会把自己的视频数报上来，弹窗会显示“视频在子页面里（N 个），本页只统计主文档”。
- **催播结果有提示**：切节后子页面按了播放会提示“子页面里的视频已自动播放”；有视频但没播起来会提示“子页面有视频，但没能自动播放，需要手动点一下”；一直没出现视频则提示“子页面里还没找到视频，先等等看”。
- **“复制结构”带上视频诊断**：新增 `TOP:` 与 `KICK:` 两行（主文档/子页面视频数、最近一次催播是否成功、地址），排查“为什么不自动播”不用再猜。

**1.3.21 的变化**：

- **播放器藏在 shadow DOM 里也能找到**：有些播放器把 `<video>` 放进自定义元素的 shadow root，`document.querySelector` 看不见。现在催播时会连 open shadow root 一起找，找到了先登记再播。
- **新增跨域播放器的回归场景**：演示页用 `127.0.0.1` 嵌 `localhost` 的播放器（跨域、外层读不到 DOM），验证“切节后由播放器那一层自己按播放”确实有效。

**1.3.20 的变化**：

- **等播放器加载出来再按播放**：1.3.19 里如果这一刻还没 `<video>`，那一层就直接退出了；但新小节是异步加载的，播放器常常晚几百毫秒。现在会在 25 秒窗口内反复等，出现了再播。
- **停在结尾的视频会从头播**：如果这一节之前已经看到最后几秒（进度续播把位置恢复到了 12:47/12:48 这种），按播放只会“闪一下结束”，看着就像没播。现在检测到“停在结尾”，会先回到 0 再播，并提示一句。

**1.3.19 的变化**：

- **切节后的自动播放，在跨域 iframe 里也能生效**：以前只有最顶层页面会去“催播”，但学习通的播放器常在跨域 iframe 里，顶层看不到里面的 `<video>`，那个 iframe 自己又因为“我不是顶层”直接放弃，于是视频停在播放按钮上。现在每一层只要自己有 `<video>` 都会催播，切完小节 25 秒内反复等它加载并按下播放。
- **只影响刚切过节的那一下**：仍然由“点下一节”时写下的时间戳驱动，120 秒内有效；平时不会去碰别的视频。


## 自动连播是怎么判断的

1. **结束检测**：优先听 `video` 的 `ended` 事件；再加上 `content/visual.js` 的画面采样兜底（视频最后 10 秒内连续 3 帧几乎相同 / 全黑 / `currentTime` 停滞）。
2. **跨 frame 协作**：每个 frame 都注入了内容脚本。视频常在跨域 iframe 里，而“下一集”按钮在外层页面，所以视频所在 frame 把“播完了”用 `postMessage` 报给顶层，顶层显示倒计时并广播“去切下一集”，每个 frame 各自找自己的候选按钮。
3. **“这一节还有几个视频没播”**：每个 frame 只看得见自己 DOM 里的视频。子 frame 每 2 秒给父 frame 发一次心跳（本层还有几个没播完、子树还有几个没播完）；一个视频播完后，所在 frame 先看自己还有没有下一个，没有就问父层；父层发现哪个子 frame 里还有没播完的，就让那个子 frame 接着播。**只有整棵 frame 树都没有没播完的视频了**，顶层才去点“下一节”。所以“页面 → 小节页 → 视频”三层嵌套也能逐层问出来，而不是简单跳到下一个章节。
4. **从当前位置往后接，不回头**：每一层把“自己的 `<video>`”和“装着视频的子 frame”按 DOM 位置排成一列；视频播完，只从它**后面**找下一个待播项；子 frame 报“我播完了”时，父层也是从那个子 frame 的位置往后接。所以你从第 3 个开始看，就接第 4、5 个，不会翻回去播第 1、2 个。切到新小节后，新内容多是异步加载的，顶层会在接下来 20 多秒里反复看一眼，把新小节的**第 1 个**视频放起来；一旦确认有视频在播就收手。
5. **候选打分**：`shared/pure.js` 里是纯函数打分（无 DOM 依赖，可单测）：
   - 自定义选择器（最高先验分）
   - `a[rel=next]`、`[data-van-next]`
   - 学习通目录适配器（当前项的下一条）
   - 播放器常见类名
   - 全站通用文本匹配：`下一集 / 下一节 / 继续播放 / next`，同时对 `上一集 / 播放列表 / 倍速` 等扣分
   - 低于阈值的一律不点——**宁可不动，也不乱点**
6. **点击后验证**：点完 2.6 秒内轮询，URL 变了 / 出现了新的播放中视频 / 进度被重置 / 页面重载，才算成功；失败就换下一个候选。

倒计时默认 5 秒，可在设置里改（0 = 立刻切）。URL 上带 `?vanDelay=2` 可以临时覆盖（自测用）。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 右下角没有悬浮面板 | 页面是装扩展之前打开的，刷新一下；`edge://` 等浏览器内部页面不注入 |
| 播完了但没自动切 | 打开设置点“在当前页面测试‘下一集’”，看顶部提示；如果提示“没找到”，说明按钮不在能识别的范围里 |
| 还在找不到 | 用开发者工具找到“下一集”按钮，复制它的 CSS 选择器，填进设置里的“自定义选择器”（每行一个） |
| 点错了按钮 | 把该按钮文字或类名反馈给我，我调整 `shared/pure.js` 里的打分规则；也可以先用自定义选择器把正确的按钮顶上去 |
| 想看它到底点了什么 | 页面顶部会闪一行提示，例如“已切换到：第 2 集” |
| 答题面板不出现 | 确认设置里开了“自动答题”，且页面是章节测验/作业；也可以临时在 URL 后加 `?vanqa=1` 强制打开 |
| 答题面板一直是“0 题” | 1.3.10 会依次试：旧版类名 → 新版文本结构 → 平级 div 的文字流 → 同源 iframe；还认不出就点面板上的“复制结构”，把复制到的内容发我（里面有 iframe 数量、同源与否、题目 HTML） |

## 已知限制

- 只有真的播放到结尾才会触发；拖进度条跳到结尾一般也会触发（`ended` 事件），但行为取决于播放器实现
- 画面识别需要能读 canvas 像素；跨域视频没有 CORS 头时 canvas 会被污染，此时会自动静默停用，只靠 `ended` 事件
- 如果站点把“下一集”做成需要登录态或额外确认的弹窗，扩展只点按钮，不处理弹窗
- 极少数站点的播放器在 iframe 里且禁用了同源访问，跨 frame 广播可能到不了，此时靠视频所在 frame 自己找按钮
- 切到下一集后会不会自动开始播，取决于站点自己的播放器：扩展只负责“点下一集”，不代替你点播放、也不制造观看记录
- “这一节还有几个视频”以视频所在 frame 的 DOM 为准：如果某个任务点的视频藏在注入不了内容脚本的 iframe 里（例如 `sandbox` 且非同源），扩展统计不到，会把它当成“这一节已经播完”
- 有些平台的视频是点开任务点时才创建出来的（懒加载）：扩展会记住“该播这个”，等它拿到数据源后再自动播一次；如果播放器非要真人点一下，悬浮面板会提示“点一下就能接着看”
- 判断“播完了”靠的是视频元素本身（`ended` / 进度到 98.5% / 画面识别），如果平台把多个视频拼成一个长视频，会被当成一集
- 答题的抓取依赖学习通常见的 DOM 类名（`.questionLi`、`.Zy_TItle`、`.Zy_ulTop` 等）；平台改版后可能需要更新 `content/answer.js` 里的选择器
- 新版章节测验现在按“`【多选题】` 标记 + A/B/C/D 行”的文本结构解析，不再要求 `input`；题干和选项是平级 div 时按文字流切题，题目在同源 iframe 里也会翻进去找。选项前缀不是 A-H（比如 ①②③）、或文字流里同一行混了题干/选项时仍可能漏，漏了就点面板上的“复制结构”，把真实 DOM 发出来补规则
- 弹题答错后会被记住并停止自动重试（同一题最多自动提交 2 次），要重新自动答，刷新页面或手动点“开始答题”即可；这是为了不让错误答案反复提交、把视频卡死
- 视频弹题依赖 `.ans-videoquiz-box` / `.ans-videoquiz-opt li` / `.ans-videoquiz-submit` 这套类名；如果平台换成别的播放器皮肤，会认不出来（面板显示“课程页面 · 0 题”），需要补选择器
- 弹题的“选中”判断靠类名（`active` / `selected` / `ans-videoquiz-opt-active` 等）；如果平台只改 `aria-checked` 或换样式名，可能点上了却仍显示“没填上”
- 填空、简答没有标准答案可校验，AI 也会答错；多选题给字母就按字母填，给选项原文就按文本匹配，匹配不上会留空并在日志里标出来
- 本地题库的相似度匹配（阈值 0.9）对“题干很长、只改一两个字”的题可能误判，所以宁可判不中留空，也不会硬填
- 自动交卷只在非考试页生效，并且会点掉页面自己画的“确认提交”框；如果平台提交前要输验证码、拖滑块或二次验证，扩展不处理，需要你自己完成
- 外层包装页能点掉确认框、点“下一节”，前提是**扩展设置里开着总开关**（真实使用是这样）；只在 URL 上带 `?vanqa=1` 的调试模式不会写进外层页面，那种页面仍需要设置里已打开答题
- 提交按钮如果内联 `onclick` 里调用了 `confirm()` / `alert()`，扩展会**跳过不点**（内容脚本在隔离世界里改不了页面的 `window.confirm`，硬点会把页面卡在原生对话框上），面板日志里会说明，需要你手动提交
- API Key 存在本机的 `chrome.storage.local` 里，不同步到其他设备；共用电脑时注意清除
